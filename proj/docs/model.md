# The model

The binding contract. Everything here was agreed before the code, and code that
contradicts it is a bug in the code, not an amendment to this file. When the
contract genuinely changes, it changes here first, in its own commit.

The board (`../board.md`) holds work. This file holds the rules the work obeys.

## Goal

One command syncs the notes you already track: newest version wins everywhere,
even when edited in both places. Sync only by Anki noteId. We track Anki notes
(one note -> N cards generated by Anki), never individual cards.

Three commands with distinct jobs: the import wizard brings Anki notes into the
vault, the export wizard creates new notes in Anki, and Sync is the only command
that updates notes on either side. Fields, tags and deck map both ways; notetype
changes and card-level properties are out of scope (ENT-07).

Card side is informational only: the `cards[]` array from `notesInfo` is never
addressed (there is no "update card #2" API). Per-card operations (e.g. suspend
one side of a reversed pair) are out of MVP scope; a card-level layer may be
added later alongside notes, not instead of them.

## Note states

State = existence x id x sync record x dirtiness. Per note:

- **ankiOnly.neverImported** — Anki-only, never imported, no sync record ->
  import (create file). Owned by the import wizard, not by Sync: Sync only
  touches tracked notes, untracked Anki notes are counted as "needs import".
- **ankiOnly.fileDeleted** — Anki-only, has sync record, file deleted in vault
  -> tombstone rule (SYNC-01/SYNC-02): resurrect iff Anki mod is newer than
  deletion.
- **synced.clean** — both sides, clean (mod and hash match records) -> do
  nothing.
- **synced.ankiNewer** — only Anki newer -> push Anki -> vault.
- **synced.vaultNewer** — only vault newer -> push vault -> Anki.
- **synced.diverged** — both dirty -> compare Anki mod vs file mtime, newer
  wins.
- **linked.unenrolled** — linked by ID but no sync record -> enroll (store mod +
  hash), then handle as `synced.*`.
- **vaultOnly.unexported** — vault-only, no ID, never uploaded -> export
  (create in Anki, write back ID + sync records).
- **vaultOnly.unenrolled** — vault-only, has ID, no sync record (fresh
  data.json, manual ID) -> match by hash, enroll, then handle as `synced.*`.
- **vaultOnly.ankiDeleted** — vault-only with ID + sync record, note gone in
  Anki -> delete file, purge records + tombstone (Anki deletion always wins).
- **orphaned** — nowhere, stale sync records -> purge records.

Two rules that cut across the list:

- Identity is per block, not per file: a deleted file and a deleted block
  inside a living file are both missing; never recreate either.
- Origin matters exactly once: an Obsidian-born note without ID must go through
  export (`vaultOnly.unexported`) first; afterwards origin is irrelevant.

The legal transitions live in `src/services/note-lifecycle.ts`, one table, with
the diagram generated from it into `docs/synchronization.md`. What each command
*does* with a note in a state lives in `src/services/sync-decision.ts`, one row
per (command, status), printed to `docs/sync-decision-table.md`. Both documents
are pinned by anti-drift tests, so neither can describe code that no longer
exists.

## Agreed sync mechanics

- **SYNC-01** — tombstones on vault delete event (reverse path -> noteId index,
  persisted noteId -> deletedAt); cleaned on sync when the note is also gone in
  Anki.
- **SYNC-02** — no tombstone (deleted outside Obsidian): Anki newer than
  recorded mod -> resurrect, otherwise respect deletion (purge, no recreate).
- **SYNC-03** — Anki deletion wins unconditionally (AnkiConnect has no deletion
  timestamps); delete file even with vault edits.
- **SYNC-04** — tie-break Obsidian wins by default; settings `syncTieWinner`
  ("obsidian" | "anki") + `syncTieThresholdSec` = 60; ties are reported.
- **SYNC-05** — missing files/blocks are skipped, counted, never recreated.
- **SYNC-06** — diverged notes are resolved by newest-wins (vault push vs anki
  pull), counted separately as pushed / refreshed.
- **SYNC-07** — mtime (`TFile.stat.mtime`, ms) is the vault-side clock vs Anki
  mod (unix seconds); own writes are safe because verdicts go through hashes
  first.
- **SYNC-08** — force is explicit and per note, offered on every row of both
  wizards, off by default, and is the mirror of SYNC-08 on the other side:
  "Anki wins" in the import wizard (FORCE_PULL from `synced.vaultNewer` and
  `synced.diverged`, RESURRECT from `ankiOnly.fileDeleted`) and "Obsidian wins"
  in the export wizard (FORCE_PUSH from `synced.ankiNewer` and `synced.diverged`,
  EXPORT from `vaultOnly.ankiDeleted`). Where the command already takes the
  preferred side, marking the row changes nothing; the report names the forced
  count, which counts only the forces that overrode a guard.
- **SYNC-09** — deck is mapped in both directions. Vault path is the source of
  truth for the target deck (`deckForPath`); a path change issues `changeDeck`
  for the cards currently in the ledger deck only; an Anki-side deck change
  (read via `cardsInfo`, `notesInfo` has no deck) moves the file to
  `deckFolder`. A note with cards in more than one deck is reported as
  ambiguous, never collapsed.
- **SYNC-10** — ignored directories are plugin-wide: no scan, no index, no ID
  filling, no purge, no import target. A ledger record whose file sits in an
  ignored folder is reported as out of scope and never purged, so the setting
  can never become a data-loss switch.
- **UX-01** — `ux/persona.md` is the reference for UX decisions (Kasia primary,
  Tomek secondary); anti-goals listed there are out of scope.

## Agreed model regime

- **MODEL-01** — export targets the source model (`extra.model`); new Obsidian
  notes always go to built-in Basic (no reverse, no cloze detection, no model
  picker in MVP).
- **MODEL-02** — models are assured on demand, only for the notes an export
  actually creates: the export plans first, collects the models its creates
  need, checks exactly those (`modelNames` + `modelFieldNames` per UC-20a),
  creates only the missing built-ins, and drops the notes of a model that is
  mismatched or name-colliding, counted in the report ("skipped on model
  mismatch"). A push reuses the Anki note's own model, which is present by
  definition, so UC-25a does not assure pushes; the real-schema check for pushes
  is UC-33a and the mapping remedy is UC-36. The all-built-ins check
  (`ensureDefaultModels`) belongs to the first-run modal (UC-39) and is never
  run as a side effect. User templates are never touched.
- **MODEL-03** — cloze means the built-in "Cloze" model only; cloze notes carry
  Anki's native fields (text, back_extra), so export is identity mapping with no
  field translation (live schema TBD, verify against Anki during UC-13: Text +
  Back Extra).
- **MODEL-04** — mapping targets mirror Anki built-ins only: Front, Back, Text,
  Back Extra (+ Skip as UI chrome, not a field).
- **MODEL-05** — exact-name (case-sensitive) auto-mapping; user maps surplus
  fields only; unmappable stays Skip; auto rows read-only, no override (auto rows
  live in advanced view, hidden by default — see UC-38 mapping visibility).
- **MODEL-06** — Add Reverse always Skip (card-generation control flag, never
  content); visible greyed out in advanced view only, hidden by default.
- **MODEL-07** — drop spaced (done: entity, parser, import branches, spaced
  regex, tests, README), drop Source entirely (done: setting, constant,
  -source variants, link injection); code-highlight still open (setting, medias,
  base64 constants ~437KB, containsCode plumbing).
- **MODEL-08** — vocabulary is Note everywhere in our code (entities, services,
  wizard, form). "Card" remains only for Anki-generated card counts in
  user-facing reports and for AnkiConnect protocol action names (`notesInfo`,
  `addNote`, ...), which are not ours to rename.
- **MODEL-09** — note-form block (fence `note-form`): one envelope, per-model
  field sets (Basic: front/back; Cloze: text/back_extra; custom: mapped fields).
  `model` is a required key; the writer always writes it (default Basic for new
  notes, never guessed cloze). The reader treats a missing `model` as Basic.
  Only editable fields are rendered by the form; `id` is hidden after assignment
  but round-trips in YAML. Unknown keys are preserved, never deleted. The
  content hash covers all synced fields + model, not just front/back/tags.
- **MODEL-10** — no migrations in MVP, period. There are no production users:
  dev notes, dev blocks and dev data.json may be discarded. No migration code
  is written for data.json, blocks, fences or mappings. A migration strategy (if
  ever needed for real users) is explicitly out of scope until post-MVP.
- **MODEL-11** — tags are per note (YAML tags field); there is no global
  flashcards tag. The `settings.flashcardsTag` key dies with the legacy cut
  (see UC-16).
- **MODEL-12** — supported built-ins are Basic, Basic (and reversed card), Basic
  (optional reversed card), Basic (type in the answer) and Cloze. Image
  Occlusion is explicitly out of MVP (known-but-unsupported: skipped with a
  direct report, never silent); masks need a canvas UI, which is a separate
  project.

## Agreed entity shape (Anki mirror)

- **ENT-01** — abstract `AnkiNote` base (noteId?, modelName, fields, tags,
  deckName, lifecycle status) + subclasses per behavior: `BasicNote` (reverse as
  flag, not a class), `ClozeNote` (cN numbering), `CustomMappedNote` (generic
  class constructed from a pack, see ENT-04).
- **ENT-02** — lifecycle = one xstate v5 machine, pure transitions only (no live
  actors; hundreds of notes x interpreters is waste without gain). The transition
  table in `src/services/note-lifecycle.ts` is the source of truth and the
  machine is generated from it, never edited directly; `transition(status, event)`
  resolves through the machine, so import/export/sync cannot bypass it. The
  conformance test in `tests/services/note-lifecycle.test.ts` is what proves the
  generation is lossless — if the machine ever disagrees with the table, that test
  is the failure. Mermaid diagram generated from the same table.
- **ENT-03** — persisted record per noteId: `{ status, updatedAt, lastMod,
  lastHash, v }` (domain record, not an xstate snapshot: snapshots embed
  version-specific internals and break rehydration after machine/library
  upgrades). `status` stores the descriptive state name (e.g. "synced.clean").
  `v` is the migration hook.
- **ENT-04** — pack JSON = one file per model (packVersion: 1, modelName + field
  mapping + derived formTemplate; never deck info). Built-in packs ship with
  the plugin (Basic, Cloze); user packs are created by the wizard for unknown
  models and reused silently on next import. A model without a pack is skipped
  by Sync + reported, never guessed.
- **ENT-05** — entity declares `formTemplate` (layout + editable/hidden fields);
  React components live in the gui layer (BasicNoteForm, ClozeNoteForm), never
  in entities. Render = f(type, lifecycle status): components may show
  per-state banners (e.g. `synced.diverged` conflict,
  `vaultOnly.ankiDeleted`, `ankiOnly.fileDeleted` resurrected).
- **ENT-06** — both wizards share code by construction: a wizard shell (page
  indicator, footer, cancel/back/next, progress) and a notes table (pagination,
  search, selection, per-row force toggle) live in a shared gui folder and are
  used by the import wizard and the export wizard; the two differ only in scope
  source (Anki deck vs vault path) and direction.
- **ENT-07** — property mapping matrix: fields, tags and deck are mapped both
  ways; notetype changes are unsupported (no AnkiConnect API, report only);
  card-level properties (suspend, flag, scheduling) are out of MVP.

## Agreed command model

The reason this plugin exists; one line per command.

- **`Import deck from Anki`** (wizard): Anki to vault for a chosen deck. Pull
  only: it never writes to Anki, never purges, never resolves deletions, and
  never overwrites a note whose vault side is newer unless the user forces that
  single note. It discovers models, maps fields, creates missing packs, shows
  the direction of every change, and writes the result report.
- **`Export deck from Obsidian`** (wizard): the exact mirror of the import
  wizard, vault to Anki for a chosen deck. Scope: one Anki deck, showing how
  many vault notes map to it and how many already exist in Anki. It creates
  missing notes, pushes what changed in Obsidian, and never guesses: a note
  edited in both places, a note newer in Anki, and a note deleted in Anki wait
  for the user, named in the report as "use Sync" or "use Obsidian wins" — the
  per-row force ("Obsidian wins", the mirror of "Anki wins", off by default,
  plus a bulk button) takes the Obsidian version regardless of state, including
  recreating a note deleted in Anki.
- **`Sync`**: the whole-ledger sweep over everything already tracked —
  bidirectional, newest version wins, no action when the ledger is empty. It is
  the command that resolves edits made in Anki in bulk, plus deletions, deck
  moves and tombstones, without asking per note. Also available for a single
  note (active file).
- Rare actions stay in the command palette (including `Purge ledger`); the
  single ribbon icon is Sync.
- Each command resolves its own states through its own resolver over the one
  transition table (`importActFor`, `exportActFor`, `syncActFor`), so the three
  commands are mirrors of each other rather than three policies: a wizard never
  resolves a conflict by clocks, only the user (force) or Sync does.

## How to work the board

Binding for every card. The same text sits at the top of `../board.md` so an
agent that only opens the board still obeys it.

- UC numbers follow execution order; work top to bottom in `Todo`.
- Definition of done per card: `pnpm run check` green (prettier, eslint, tsc,
  knip, jest, jscpd, dependency-cruiser, in that order); nothing else touched.
- Each card states its done-when up front, and the red test comes first per
  `AGENTS.md`. "Re-validate" means existing tests green with no logic change,
  nothing more.
- Phase 0b renames changed names only: no assertion changes, no logic changes.
  If a rename forces a logic change, the card is misscoped — split it.
- One card = one commit, and the commit message names the card id.
- A card that gets decided out of scope leaves the board for
  [decisions.md](decisions.md) with the reason and the condition to revisit it.
